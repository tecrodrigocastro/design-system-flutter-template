# mcp_server

An [MCP](https://modelcontextprotocol.io/) server, written in Dart with
[`package:dart_mcp`](https://pub.dev/packages/dart_mcp), that exposes the
[`design_system`](../design_system) package's component catalog to AI
coding assistants — so they can look up a component's exact props, an
enum's valid values, or a token's literal color instead of grepping
source or guessing.

## Why two data sources

- **`package:analyzer`** parses `design_system/lib` directly (syntax only,
  no build graph) into a structured catalog: every component's params
  (type, required, default, doc), every enum's values, every token's
  literal value. This is what `get_component`, `get_token`, and
  `get_enum` read from — always in sync with the source, no separate
  build step.
- **`design_system/doc/api/index.json`**, generated by `dart doc`, backs
  `search_docs` — a free-text index for when you don't know the exact
  symbol name. Regenerate it with `dart doc .` inside `design_system/`
  whenever you want search results to reflect the latest docs.

## Tools

| Tool | Description |
| --- | --- |
| `list_components` | List every `Ds*` widget, optionally filtered by `category` (`atom`/`molecule`/`organism`). |
| `get_component` | Full schema for one component: doc (with its usage example), and every constructor param. |
| `list_tokens` | List every design token class and the members it exposes. |
| `get_token` | Literal values for one token class, e.g. `DsPrimary.base` → `Color(0xFF782DC8)`. |
| `list_enums` | List every variant/size enum. |
| `get_enum` | Every value of one enum, with its doc. |
| `search_docs` | Free-text search over the dartdoc index. Requires `dart doc .` to have been run first. |

## Running it

```sh
cd mcp_server
dart pub get
dart run bin/mcp_server.dart
```

By default it looks for the design_system package at `../design_system`
(the monorepo layout). Override with `--design-system-root=<path>` or the
`DESIGN_SYSTEM_ROOT` environment variable if you're using this outside
the template.

## Configuring an MCP client

Point your client at `dart run bin/mcp_server.dart` with this directory
as the working directory. For Claude Code / VS Code / other clients that
read a `.mcp.json`:

```json
{
  "mcpServers": {
    "design_system": {
      "command": "dart",
      "args": ["run", "bin/mcp_server.dart"],
      "cwd": "mcp_server"
    }
  }
}
```

This is separate from — and complements — the official
[Dart MCP server](https://docs.flutter.dev/ai/tools) (`dart mcp-server`),
which gives an agent general Dart/Flutter tooling (analyze, test,
format, pub search). This server only knows about this repo's own
design system.

## Regenerating and testing

```sh
dart analyze
dart test
```

`test/design_system_mcp_server_test.dart` runs the real MCP protocol
(initialize, tools/list, tools/call) over an in-memory channel — no
subprocess needed for the fast suite.
